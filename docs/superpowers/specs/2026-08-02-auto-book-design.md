# auto-book v1 设计文档

日期：2026-08-02
状态：已确认，待实现

## 1. 产品意图

一个把读书笔记自动变成短视频的工具，服务两个目标：

1. **记录读书** —— 划线和想法沉淀成结构化素材
2. **倒逼输出** —— 想法必须写出来才能变成视频，公开发布形成压力

两个目标存在张力：AI 干得越多越省事，学到的越少。设计上不消除张力，而是**显式提供两档模式**，由使用者按当天状态选择。

单人自用起步，数据模型预留多用户。

## 2. 已确认的产品决策

| 维度 | 决策 |
|---|---|
| 输入方式 | 内置 EPUB 阅读器（主）+ 公众号速记 + 网页粘贴（降级）|
| 输出形态 | 竖屏短视频 60–90s；纯文字排版卡片；不出脸 |
| 配音 | 默认 AI 配音，深耕档可用自己录音 |
| 平台 | 抖音、小红书、视频号（视频）+ 公众号（长文）|
| 发布 | **全部手动**。不做浏览器自动化，规避封号风险 |
| AI 分工 | 双档：深耕档（AI 提问，我回答）/ 快产档（AI 出稿，我审改）|
| 用户模式 | 单用户起步，所有表带 `user_id`，v1 固定为 1 |
| 渲染技术 | Remotion（React/TS 写视频）|
| 视觉调性 | 深色主调 + 米色翻转 + 金色点缀；克制，不喧闹 |

### 未采纳及原因

- **数字人口播** —— 按分钟计费、口型出戏，且知识类账号中降低信任。推迟至 v2 后。
- **自动发布** —— 抖音/小红书/视频号无开放 API，浏览器自动化有封号风险且页面改版即失效。
- **二次开发 MoneyPrinterTurbo** —— 其核心价值是"关键词→图库素材匹配"，与本项目的文字排版路线无重叠；架构假设差异大，二开会持续冲突。**仅参考**其 edge-tts 调用方式、字幕断句规则、中文字体处理和 ffmpeg 参数。

## 3. 视频结构：五帧

五帧结构是全系统的**唯一真源**。它同时是 AI 的输出格式、Remotion 的组件划分、以及后续图文形态的数据基础。

| 帧 | 时长 | 内容 | 视觉 |
|---|---|---|---|
| ① Hook | 0–3s | 钩子短句，抢住前 3 秒 | 深色底，大字压屏 |
| ② Quote | 3–14s | 原文金句 + 划线日期 + 阅读进度 | 米色底翻转，衬线体 |
| ③ Breakdown | 14–34s | 作者观点拆解，2–3 条 | 深色底，逐条浮现 |
| ④ MyTake | 34–54s | **我的想法**，鼓励写出分歧 | 独立配色，左侧竖线标记 |
| ⑤ Outro | 54–60s | 提问收尾 + "第 N 本 / 年份" | 米色底，落款 |

### 为什么是这个结构

第 ② 帧的划线时间戳证明"真读过"，第 ④ 帧的个人观点（尤其是与作者的分歧）证明"真想过"。这两点批量洗稿的账号无法伪造，是内容的唯一差异化来源。其余三帧是承载它们的必要结构。

## 4. 架构

```
auto-book/
├── backend/              Python 3.12 · FastAPI
│   ├── api/              HTTP 接口
│   ├── core/
│   │   ├── script.py     DeepSeek → 五帧脚本 JSON
│   │   ├── tts.py        edge-tts → 音频 + 逐词时间戳
│   │   ├── caption.py    时间戳 → 每帧字幕分段
│   │   ├── render.py     调用 Remotion CLI
│   │   └── copywrite.py  DeepSeek → 各平台标题/文案/标签
│   ├── models.py         SQLModel · SQLite
│   └── schema/frames.py  五帧结构定义（唯一真源）
├── video/                Remotion · TS
│   └── src/
│       ├── Book60.tsx    主 Composition
│       ├── frames/       Hook / Quote / Breakdown / MyTake / Outro
│       └── theme.ts      配色、字体、间距
├── web/                  Vite + React + TS
├── assets/fonts/         思源宋体、思源黑体（嵌入，不依赖系统）
└── storage/              素材、音频、成品（不进 git）
```

### 模块边界

- **`schema/frames.py`** —— Pydantic 定义五帧结构，导出 JSON Schema，Remotion 侧据此生成 TS 类型。改结构只改一处。
- **`core/*`** —— 每个模块单一职责，输入输出都是纯数据，可独立测试，不依赖 HTTP 层。
- **`video/`** —— 只消费五帧 JSON，对后端零依赖，可用假数据独立预览开发。

### 数据流

```
POST /jobs (material_id, mode)
  → pending → scripting → tts → rendering → done | failed
  → 前端轮询 GET /jobs/{id}
  → done 后 GET /jobs/{id}/assets 下载 MP4 + 文案
```

状态机持久化在 `Job` 表，失败记录错误原因，可重试。

### 数据模型

所有表含 `user_id`（v1 固定 1）与 `created_at`。

- **`Book`** —— 书名、作者、封面路径
- **`Material`** —— `book_id`、原文、我的想法、位置、阅读进度、来源(`epub`/`paste`/`wechat`)、`mode`(`deep`/`fast`)
- **`Job`** —— `material_id`、状态、五帧脚本 JSON、错误信息、token 成本
- **`Asset`** —— `job_id`、类型(`audio`/`video`/`caption`)、文件路径

`mode` 字段的用途不是限制，而是留出数据：哪一档产出的视频表现更好，年底有多少内容是真正想过的。

## 5. 技术选择

**渲染在本地** —— 开发与渲染均在本地 Mac。2核4G 服务器跑 headless Chrome 渲视频过于紧张，且 v1 只有单一使用者，本地渲更快且零成本。服务器保留给 v2 的公众号接口（需公网 HTTPS）。

**字体嵌入** —— 思源宋体（金句正文）+ 思源黑体（标签、字幕），随项目分发，不依赖系统字体。中文视频渲染最常见的失败原因就是字体缺失导致方框。

**字幕对齐** —— edge-tts 的 `WordBoundary` 事件提供每词偏移与时长。按标点优先、单行 12 字上限断句，输出每段的起止帧号交给 Remotion。

**AI 模型** —— DeepSeek。中文表现好，成本在预算内可忽略（月成本量级为个位数到几十元）。

**TTS** —— edge-tts，免费且提供逐词时间戳。腾讯云 TTS 作为备选（约 ¥100/百万字符，单条视频不足 3 分钱）。

## 6. 安全设计

- **密钥** —— DeepSeek key 仅从环境变量读取，代码中无任何默认值或回退值。`.env` 列入 `.gitignore`。
- **命令执行** —— 调用 Remotion CLI 使用 `subprocess` 列表参数且 `shell=False`。所有路径参数经白名单校验，绝不拼接用户输入。
- **路径穿越** —— 文件下载接口对路径做规范化并校验前缀落在 `storage/` 内。
- **网络暴露** —— v1 仅监听 `127.0.0.1`，不暴露公网。
- **输入长度** —— 素材文本入库前设长度上限，防止超长输入打爆 AI 调用与渲染。
- **XSS** —— 前端渲染依赖 React 默认转义，不使用 `dangerouslySetInnerHTML`。
- **外部请求** —— v1 仅访问 DeepSeek 与 edge-tts 两个固定外部地址，不接受用户提供的 URL，无 SSRF 面。v2 引入封面抓取等功能时需重新评估。

## 7. v1 范围

### 做

1. 网页粘贴入口：书名 + 原文 + 我的想法
2. DeepSeek 生成五帧脚本
3. edge-tts 配音 + 逐词时间戳
4. 字幕分段与对齐
5. Remotion 渲染 1080×1920 / 60s MP4
6. 生成抖音、小红书、视频号三版标题+文案+标签
7. 任务状态机与错误反馈

### 不做

EPUB 阅读器、公众号双向接口、登录与多用户界面、素材库管理界面、深耕档 AI 提问、自己录音上传、BGM 素材库（固定一首或无）、小红书图片卡、公众号长文、任何自动发布。

### 验收标准

1. 网页贴入素材，点击生成
2. 90 秒内产出 1080×1920、约 60 秒、含完整五帧的 MP4
3. 字幕与配音对齐误差 < 0.3 秒
4. 同时产出三平台文案
5. 失败给出明确错误信息，不静默失败
6. 中文字体、标点、换行全部正常，无方框、无溢出

## 8. 后续路线

- **v2** —— EPUB 阅读器（划线即存素材）；公众号双向接口（速记入口 + 长文草稿）；深耕档 AI 提问
- **v3** —— 小红书图片卡与公众号长文（复用同一套排版组件）；素材未加工提醒；自己录音上传
- **待验证后决定** —— 是否开放多用户；数字人口播是否需要

v1 上线后先看真实流量数据，再决定下一步优先级。
